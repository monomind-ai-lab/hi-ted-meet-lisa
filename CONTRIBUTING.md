# Contributing to Hi Ted, Meet Lisa

Thank you for your interest in making Hi Ted, Meet Lisa better! We welcome contributions in two main ways:

---

## 1. Make it better together

Help us improve Hi Ted, Meet Lisa by reporting bugs, requesting features, or suggesting new templates.

### Report bugs
If you find something that doesn't work as expected:

1. **Open an issue** with a clear description of the problem
2. **Include steps to reproduce** — what deck type were you building? What input triggered it?
3. **Show what you expected** — what should have happened instead?
4. **Mention your environment** — which agent, browser, and OS you're using

### Request features
Have an idea for a new capability?

1. **Search existing issues** first to see if someone else suggested it
2. **Open an issue** with the label `enhancement` describing:
   - What you want to do that isn't possible now
   - Why it matters to you
   - How you imagine using it

### Request new templates
Want a template shape Hi Ted, Meet Lisa doesn't have yet?

1. **Describe the use case** — what kind of deck or document would you build?
2. **Show an example** — a screenshot, link, or description of a deck you'd want to create
3. **Explain what's missing** — why existing templates don't quite fit

---

## 2. Submit artifacts to showcase

Share decks you've built with Hi Ted, Meet Lisa. Approved artifacts help show what's possible and inspire others.

### What we're looking for

- **Real decks you've created** — anything you've shipped using Hi Ted, Meet Lisa
- **Diverse use cases** — presentations, documentation, architecture diagrams, proposals, handbooks
- **Different styles** — each template type represented, different color schemes, both light and dark examples
- **Genuine work** — decks built for real audiences and purposes (internal or external)

### How to submit

1. **Create an issue** with the label `artifact-submission` containing:
   - A **link to your deck** (or the `.html` file itself)
   - **A brief description** — what is the deck about? who is the audience?
   - **The template used** — MonoMind deck, Web document, Architecture diagram, etc.
   - **Permission confirmation** — you confirm you have the right to share it

2. **What happens next**:
   - We review the deck for content (checking for malware, harmful content, or sensitive data)
   - Once approved, we add it to a showcase gallery
   - You're credited as the creator

### Privacy & safety

We run basic security checks to protect the community:
- Scans for malware or suspicious code injection
- Review for harmful, fraudulent, or sensitive content
- Verify no credentials or personal data are embedded

Your real name isn't required — you can submit under a pseudonym or organization name.

---

## Code of conduct

Keep the community welcoming:

- Be respectful to other contributors and maintainers
- Assume good intent — we're all here to make decks better
- Help others learn if they're new to templates or HTML
- No spam, promotional links, or off-topic posts
